# 加载、动作节奏与自动验收

0.1.27 的正式客户端按需读取当前角色的素材。源码保留原始 PNG、高清图层与角色工程，安装包只包含运行代码、原生角色无损归档、八份内置角色 ZIP 与示例包。

## 本次测量

| 项目 | 优化前 | 优化后 |
| --- | --- | --- |
| 安装 TGZ | 约 117 MB | 约 52 MB |
| 正式客户端脚本 | 约 19.6 MB | 约 0.32 MB |
| 高清／像素来回切换 | 再次解码、扫描角色 | 命中缓存后不再解码 |
| 静止待机的完整画布重画 | 跟随前台刷新回调 | 实测约每秒 8 次 |

数值使用本机 0.1.27 构建、`npm run package:check` 与 `npm run test:browser` 测得。它们表示包大小、解码次数和绘制次数，不等同于 CPU 或内存占用的百分比。开发预览为了完全离线，会通过单独模块内嵌完整 ZIP；其页面脚本大小不能作为正式客户端大小。

原生 Deep seek 的九张动作源图在构建时转换为 RGBA 无损 WebP，放入 `assets/runtime/native-sprites.zip`；逐像素测试对照原 PNG，确认头脸、鞋形和比例不变。仅显式选择该角色或需要原生回退时才读取。角色选择卡片使用小缩略图，打开面板不会解码全部角色图集。

## 解码缓存与绘制

客户端使用按最近访问顺序淘汰的解码缓存，预算按图片宽 × 高 × 4 估算为 128 MiB。缓存命中会复用同一个图片及边界结果；并发请求去重，失败后可重试，导入同 ID 新包或删除时使旧缓存失效。切背景时复用角色。渲染器和650毫秒转场仍持有正在使用的图片，因此缓存预算不代表浏览器进程总内存上限。

内置角色只有在动作帧、人物位置、场景帧或显示状态变化时才完整重画。行走、扫描转场保持动态刷新，自定义包保留其自定义时长。后台、收起和系统“减少动态效果”继续按既有规则暂停。

## 任务动作的可读时间

实际任务中的普通动作至少展示约500毫秒，仅保留最新待展示阶段，避免密集工具调用不断切回第一帧。状态文字立即更新；新任务、完成、失败和取消立即打断等待。每帧仍为125毫秒，动作速度不变。预览按钮默认立即切换；`?form=hd&action=reading&timing=live` 可模拟同一任务内的连续阶段。

## 自动检查

```powershell
npm run typecheck
npm test
npm run characters:check
npm run package:check
npx playwright install chromium
npm run test:browser
```

`build`、`typecheck`、`test` 和 `preview` 会按需生成并复用运行资源，无需手工提交 `assets/runtime/`。打包检查逐字节核对所有安装文件，要求客户端低于512 KiB、安装包低于64 MiB，并检查正式构建没有内嵌完整人物素材。

浏览器验证启动自己的临时预览服务器，完成后关闭。它检查26套动作的八帧播放、两形态缓存复用、切背景、协作扫描、暂停、原生选择刷新恢复、卡片与窄屏布局，以及真实任务节奏下对密集阶段的合并和完成优先级。截图和记录保存在 `work/browser-tests/`；打包记录在 `work/package-check/validation.json`。

GitHub 的 `Plugin checks` 在 PR 和主分支提交上自动运行：Linux、Windows 均检查构建、类型和测试；Linux 增加人物、包体和浏览器验证；Windows 增加隔离的桌面更新器集成测试。检查报告、截图和已验证安装包作为构建产物保留7天，不自动发布 Release 或安装桌面插件。

CI 使用 `npm run test:ci` 串行运行测试文件，避免图片解码校验占满共享 runner 的 CPU 后干扰场景的80毫秒执行保护。运行时限制保持原值；本地 `npm test` 仍并行运行。
